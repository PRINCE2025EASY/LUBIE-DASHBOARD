# Use case specifications (15 most important)

Companion to `docs/diagrams/08-use-case-diagram.drawio`. Version 0.2.0, 21/10/2026. Requirement IDs refer to `docs/stage1/05_Master_Requirements.md`.

| ID | Use case | Actor(s) | Preconditions | Main flow | Alternative / exception flows | Postconditions | Requirements |
|---|---|---|---|---|---|---|---|
| UC01 | Log in (includes UC02 Redirect to role dashboard) | All six roles | Account exists and is active; HTTPS in production | 1. User opens the one login page. 2. Enters username and password. 3. System checks CSRF and rate limit, verifies the hash, loads role from the database. 4. System regenerates the session ID, logs `login`. 5. UC02: redirect to `/admin`, `/director`, `/pm`, `/qs`, `/site` or `/client`. | A1 wrong credentials or unknown user: generic message, failure counted, `login_failed` logged. A2 fifth failure: account locked 15 min. A3 must change password: redirect to change-password page first. A4 already logged in: login page redirects to own dashboard. A5 return-to page allowed only if the role may view it. | Authenticated session; audit row | FR-01, FR-02, FR-03, FR-29, NFR-01 |
| UC08 | Record progress | Site Engineer, PM | Logged in; assigned to the project; activity active | 1. Open My activities. 2. Choose activity (shows planned %, last approved %). 3. Enter % (0-100), date (today pre-filled), delay reason, remarks. 4. Submit. 5. System validates, stores as Submitted, raises A13 (and A15 for stoppage or safety), shows "Submitted". | A1 invalid value: field errors, input kept. A2 network failure: draft kept, "Not saved" (FR-37); with offline mode, UC09 queues it. A3 activity archived meanwhile: 409 with message. | Submitted record; PM notified | FR-09, FR-30, FR-32, FR-37, NFR-08 |
| UC10 | Approve or return progress | Project Manager | Submitted entries exist on an assigned project | 1. Open approval queue. 2. Review entry against plan. 3. Approve. 4. System marks Approved, recalculates KPIs, evaluates alerts (UC25), clears A13, logs audit. | A1 Return: PM gives a reason; status Returned; submitter sees the reason and may submit a corrected entry. A2 entry already decided: 409. | Only approved progress counts in KPIs | FR-30, FR-10, FR-11, FR-20 |
| UC11 | View project dashboard and KPIs (includes UC12) | Director, PM, QS, Site Engineer | Logged in; Director any project, others assigned | 1. Open project. 2. System builds the role-filtered DTO: KPI cards with formula tooltips, PV/EV chart, budget vs expenditure chart (not for SE), delayed activities, milestones, open alerts, last updated. 3. Page polls `/changes` every 60 s and redraws on change. | A1 no approved progress: KPIs show "not available" text. A2 polling fails: banner and backoff. A3 not assigned: 404/403, audit `forbidden`. | Current view shown; no data changed | FR-10 to FR-13, FR-16, FR-17, FR-23, FR-24 |
| UC13 | Compare portfolio of projects | Director | Logged in as Director | 1. Open portfolio. 2. System lists every non-archived project with % complete, SV, CV, delayed count, next milestone, critical alerts, status (colour, text, icon). 3. Director opens a project (read-only UC11). | A1 no projects: empty state. | None | FR-35, FR-23 |
| UC14 | Record budget and request revision | QS, PM | Assigned project | 1. QS records baseline v1 (Director approves via UC15). 2. Later, QS or PM creates a revision with amount and reason. 3. Submits; status Pending; A12 raised; Director notified by SMS when enabled. | A1 save as draft only. A2 amount negative: rejected. | Pending version; history kept | FR-14, FR-31, FR-20 |
| UC15 | Approve or reject budget revision | Director | Pending revision exists | 1. Open pending revisions. 2. Review amount, reason, history. 3. Approve. 4. System supersedes the old current version and makes the new one current in one transaction; clears A12; re-evaluates budget alerts; audit. | A1 Reject with note. A2 Director is the requester: refused (separation of duties). | One current approved budget | FR-31, FR-14 |
| UC16 | Record expenditure (includes UC25) | Quantity Surveyor | Assigned project; current budget exists for budget KPIs | 1. Enter date, amount, category, description, reference, supplier, optional activity. 2. Confirm (single-source field check). 3. System stores, updates AC, evaluates A5, A6, A6b, A7. | A1 duplicate reference: 409. A2 correction: void with reason (no delete). | Expenditure recorded; alerts current | FR-15, FR-16, FR-20 |
| UC17 | Record valuations and payments (includes UC25) | Quantity Surveyor | Assigned project | 1. Record valuation certificate (number, amount, submitted date). 2. Certify (amount, date). 3. Record one or more payments. 4. System shows paid, outstanding, status; evaluates A9. | A1 overpayment: 422. A2 duplicate certificate number or payment reference: 409. | Certificate and payment history; client totals updated | FR-28, FR-20 |
| UC18 | Record resources and material requests | Site Engineer, PM | Assigned project | 1. Record labour attendance, material receipt or use, equipment status. 2. Raise a material request. 3. PM approves, marks delivered or cancels. 4. System updates balances; A10 when below reorder level; A14 when equipment faulty. | A1 use exceeds balance: warning, confirm. A2 offline (It.2): queued via UC09. | Resource records and request status | FR-18, FR-19, FR-33, FR-34 |
| UC19 | Set alert thresholds | Director (global), PM (project), QS (propose) | Logged in with that role | 1. Director sets global value and limits. 2. PM sets a project value. 3. System checks it lies within the global limits, saves, audits, re-evaluates alerts. | A1 outside limits: 422 with allowed range. A2 QS proposal: stored as pending; Director approves or rejects. | Effective thresholds updated | FR-21, NFR-10 |
| UC20 | Receive and manage alerts (extended by UC21) | Director, PM, QS, Site Engineer; Client (A4 notice only) | Alert exists for the user | 1. Bell shows unread count. 2. User opens the alert panel, reads and acknowledges. 3. Alert resolves itself when the condition clears. | A1 Critical or High with SMS level: UC21 sends SMS within caps. A2 cap reached: logged as capped; in-app only. | Read and acknowledged states recorded | FR-20, FR-22 |
| UC22 | Export reports (includes UC12) | Admin, Director, PM, QS; Client (own summary) | Permission for the report type | 1. Choose report, project, dates, format. 2. System applies the same permissions and calculations as the dashboard, streams PDF or CSV, logs `export`. | A1 not permitted: 403 and audit. A2 no data: report with "No records" line. | File downloaded; nothing stored on the server | FR-26, NFR-01 |
| UC23 | View client summary (includes UC12) | Client | Client assigned to the project | 1. Client logs in and lands on the one-screen summary. 2. System shows overall %, milestone timeline, contract sum, certified, paid, outstanding, last updated, A4 notices. 3. Client may download the one-page PDF. | A1 project not assigned: 404 and audit. | None | FR-27, FR-26 |
| UC05 | Back up and restore data | Administrator, External scheduler | Backup token and encryption key configured | 1. Scheduler calls the protected endpoint daily (or Admin presses Back up now). 2. System streams an encrypted, compressed dump and logs it. 3. File stored off-site. 4. Monthly, Admin runs restore:verify into a separate database and records the result. | A1 invalid token: 401 and audit. A2 restore check mismatch: use previous backup and investigate. | Verified backup chain; RPO 24 h, RTO 4 h evidence | FR-36, NFR-06 |

UC09 (Work offline and sync, Iteration 2) is specified in Design Specification s13. UC03, UC04, UC06, UC07, UC24 and UC12 follow standard create, read, update patterns described in the API specification (Design Specification s8).
